# Публикация на GitHub

Адрес проекта: https://github.com/ztfy404/wazuh-siem-lab. Ниже сохранена инструкция публикации для новых копий проекта. Скриншоты добавляются отдельными коммитами после обезличивания; исходные файлы виртуальных машин и секреты в Git не включаются.

## Через сайт

1. Создать репозиторий `wazuh-siem-lab` в своём GitHub.
2. Выбрать видимость. Для публичного портфолио — Public; если сначала нужна проверка материалов, можно начать с Private.
3. Через **Add file → Upload files** загрузить **содержимое** папки проекта, чтобы `README.md`, `docs/`, `configs/` и остальные каталоги лежали в корне репозитория. ZIP загружать вместо распакованного проекта не нужно. Скрытый `.gitignore` убедиться, что тоже добавлен; при необходимости создать через Add file.
4. Заполнить About и Topics из [portfolio.md](portfolio.md).
5. В профиле GitHub выбрать **Customize your pins** и закрепить проект.

## Через Git

Войти в свою учётную запись обычным способом GitHub: браузер/OAuth, менеджер учётных данных или SSH. Токены в README, команды с URL или этот чат не вставлять.

Создать на GitHub **пустой** репозиторий без автоматически созданных README/лицензии, затем в распакованной папке выполнить:

```bash
git init -b main
git add README.md .gitignore docs configs scripts evidence screenshots
git status
git commit -m "Document Wazuh SIEM lab"
git remote add origin https://github.com/YOUR_USERNAME/wazuh-siem-lab.git
git push -u origin main
```

Заменить `YOUR_USERNAME`. Имя и email автора коммита задать в локальной конфигурации Git при необходимости; можно использовать GitHub noreply email. Команды выше предназначены для нового репозитория, не для перезаписи существующего.

## Что добавить из исходных материалов

- Обезличенные скриншоты активного агента, Dashboard, SSH/sudo и FIM.
- Версии пакетов, точные rule ID и временные метки сценариев.
- Проверенные исходные конфигурации без регистрационных ключей и паролей.

Порядок доказательств: [screenshots/README.md](../screenshots/README.md). Реестр: [evidence/manifest.csv](../evidence/manifest.csv). После добавления обновить статусы в README и results.md. Не удалять оговорку о восстановленных примерах, пока они не заменены реальными материалами.

## Секреты и лицензия

Перед публикацией просмотреть снимки и файлы: не включать пароли, ключи агентов, приватные ключи, токены и персональные данные. `.gitignore` помогает избежать случайного добавления, но не удаляет секрет из истории Git, если он уже попал в коммит.

Файл LICENSE намеренно не выбран автоматически: условия распространения своих материалов определяет автор. При выборе лицензии не включать в неё чужие бинарные пакеты, логотипы и материалы без необходимых прав.

## Добавление скриншотов в этот проект

Для существующего репозитория не повторять `git init` и `git remote add`. Открыть `screenshots/` на GitHub, загрузить обезличенные изображения и обновить `evidence/manifest.csv`, `docs/results.md` и ссылки в README. Либо изменить файлы в своей локальной копии, создать обычный коммит и выполнить `git push`.
