# Что я проверял

Я проверял события SSH, использование `sudo` и изменения файлов в тестовом каталоге. Ниже оставил команды для повторения похожих проверок. Это не экспорт моей истории команд.

## SSH

Я посмотрел события SSH в `/var/log/auth.log`, а затем нашёл их в Threat Hunting. Для поиска важны нужный агент и правильный диапазон времени.

Для повторной проверки можно подключиться к своей Astra Linux:

```bash
ssh LAB_USER@ASTRA_AGENT_IP
```

Если на машине разрешён вход по паролю, можно один раз ввести неверный пароль своей тестовой учётной записи и посмотреть результат. При входе только по ключу менять SSH-настройки ради этого не нужно.

Нужно сравнить время и содержание записи в Linux с событием в Dashboard. Наличие записи только в `auth.log` ещё не означает, что она дошла до Wazuh.

## sudo

Я также проверял регистрацию событий `sudo`. Пример простого действия для повторения:

```bash
sudo -k
sudo /usr/bin/id
```

Первая команда сбрасывает кеш пароля `sudo`, вторая выводит идентификаторы пользователя. Настройки пользователей и права эти команды не меняют. После выполнения можно найти запись в журнале и событие в Wazuh.

## Изменения файлов — FIM

Я настроил наблюдение за `/opt/siem-fim-test/` и проверял создание, изменение и удаление файла.

Перед повторением каталог должен существовать и быть включён в FIM. Нужно дождаться начального сканирования. Пример настройки лежит [здесь](../configs/examples/fim-syscheck.fragment.xml).

Пример создания тестового файла:

```bash
sudo mkdir -p /opt/siem-fim-test
FIM_FILE="/opt/siem-fim-test/portfolio-$(date +%s)-$$.txt"
sudo test ! -e "$FIM_FILE"
# Продолжать, только если такого файла ещё нет и команда вернула код 0.
printf 'Wazuh FIM test\n' | sudo tee "$FIM_FILE" >/dev/null
```

Изменение в том же терминале:

```bash
printf 'File changed\n' | sudo tee -a "$FIM_FILE" >/dev/null
```

Удаление только этого тестового файла:

```bash
sudo rm -- "$FIM_FILE"
```

Между действиями нужно дождаться события. Если сделать всё подряд, отдельные изменения могут не отобразиться так, как ожидается. Для проверки realtime-режима я оставил [пример XML](../configs/examples/README.md); его нужно сверить со своей конфигурацией.

Точные rule ID, уровни и скриншоты отдельных событий добавлю после разбора сохранённых материалов. Пока не указываю их наугад.
