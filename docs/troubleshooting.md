# Диагностика и известные проблемы

В предоставленном описании есть проблемы и итоговые решения, но нет полного хода диагностики. Поэтому не все причины можно установить достоверно.

| Ситуация | Что известно | Что нельзя утверждать |
|---|---|---|
| Первые попытки установки | До итоговой Ubuntu 24.04 использовалась Ubuntu 26.04.1; финальный стенд на 24.04 | Не доказана конкретная причина неудачи или несовместимость релиза |
| Indexer не запускался | Проблемы запуска устранены, служба работала | Нет точной ошибки, причины и команды исправления |
| Сеть и SSH | После сложностей с NAT выбран Bridged Adapter | NAT сам по себе не исключает связь; причина и параметры проброса не сохранены |
| Место на диске сервера | Диск вырос с примерно 25 ГиБ до 85 ГБ | Не известны схема разделов, команды и точная причина расширения |

## Полезный порядок повторной диагностики

Эта последовательность добавлена при оформлении, а не извлечена из истории команд автора:

1. Убедиться, что ВМ запущены и имеют согласованные ресурсы и адреса.
2. Проверить активность нужной службы через `systemctl is-active`.
3. Локально прочитать `systemctl status` и `journalctl` для конкретной службы.
4. Для агента проверить адрес Manager, регистрацию и журнал агента.
5. Для отсутствующего события проверить источник на узле, время, агента и диапазон поиска Dashboard.
6. Для цепочки индексации использовать `filebeat test output`; успешная связь сама по себе ещё не доказывает наличие конкретного события.
7. Записать «симптом → причина с доказательством → изменение → повторная проверка».

Не включать в портфолио непроверенные причины ошибок и не представлять переустановку как установленную первопричину.
