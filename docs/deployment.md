# Развёртывание Wazuh All-in-One

## Статус инструкции

Порядок восстановлен из описания автора. Исходный журнал команд и установочные файлы не переданы; ниже не заявляется точное воспроизведение команд проекта. ВМ повторно не развёртывались при оформлении репозитория.

По описанию итоговая ОС — Ubuntu Server 24.04 LTS; версия Wazuh — 4.14.10. Перед повторением проверить установленную версию и совместимость выбранного релиза в документации производителя. Ссылка `current` может описывать другой релиз.

## 1. Подготовить виртуальную инфраструктуру

- Создать серверную ВМ Ubuntu Server 24.04 LTS и отдельную ВМ Astra Linux.
- Согласовать CPU, RAM и диски с физическим хостом: [ресурсы](architecture.md).
- Настроить доступность ВМ друг для друга и административного клиента. В проекте итоговым режимом стал Bridged Adapter.
- Зафиксировать IP, часовой пояс, синхронизацию времени и свободное место. Настройки времени и firewall исходного проекта не сохранены, это шаги проверки при повторении.

## 2. Установить серверные компоненты

Использовать официальный [Quickstart Wazuh](https://documentation.wazuh.com/current/quickstart.html) с выбором документации нужного релиза. В проекте выбран All-in-One: Manager, Indexer и Dashboard расположены на одной ВМ; Filebeat передаёт данные в Indexer.

Точная команда запуска установщика, параметры и контрольная сумма в исходных материалах отсутствуют. Поэтому репозиторий не содержит непроверенного скрипта автоматической установки. Сохранить использованный способ и версии пакетов при повторении, не добавляя установочные секреты в Git.

## 3. Проверить компоненты

На серверной ВМ:

```bash
systemctl is-active wazuh-manager wazuh-indexer filebeat wazuh-dashboard

dpkg-query -W -f='${binary:Package}\t${Version}\n' \
  wazuh-manager wazuh-indexer wazuh-dashboard filebeat

sudo filebeat test output
```

Ожидается активность всех служб и успешное соединение Filebeat с Indexer. По описанию автора TLS handshake и подключение уже проходили проверку; исходный вывод не приложен. Проверка `filebeat test output` выполняется на сервере с установленной и настроенной службой; её вывод не следует публиковать без просмотра.

Для диагностики по необходимости:

```bash
sudo systemctl status wazuh-indexer --no-pager
sudo journalctl -u wazuh-indexer -n 50 --no-pager
```

Диагностические команды могут показывать внутренние сведения. Полные логи автоматически в репозиторий не собираются.

## 4. Проверить Dashboard

Открыть `https://WAZUH_SERVER_IP` с административного клиента. Использовать собственные учётные данные; в примерах они не публикуются. Зафиксировать доступность интерфейса и установленную версию. Проблемы доверия сертификату диагностировать отдельно; отключение TLS-проверки не используется как критерий исправной настройки.

## 5. Подключить источник и проверить события

Следовать [инструкции агента](agent-setup.md), затем [контрольным сценариям](detection-tests.md). Прикрепить обезличенные снимки и [обновить результаты](results.md).

## Не зафиксированные настройки

Не известны: точная версия VirtualBox и Filebeat, итоговые ресурсы обеих ВМ, параметры установщика, правила firewall, настройки сертификатов, retention и экспорт исходных конфигов. Эти значения нельзя восстановить достоверно из краткого описания.
