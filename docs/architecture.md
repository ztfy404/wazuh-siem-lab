# Архитектура стенда

## Узлы

| Узел | ОС / роль | Известные сведения |
|---|---|---|
| Физический компьютер | Windows 10, Oracle VirtualBox | 16 ГБ RAM; точная модель CPU не указана |
| Серверная ВМ | Ubuntu Server 24.04 LTS x86_64 | Wazuh All-in-One, версия по описанию 4.14.10 |
| Контролируемая ВМ | Astra Linux Orel 2.12.46 x86_64 | Wazuh Agent, версия по описанию 4.14.10 |

Windows-агент не устанавливался. Облачные сервисы и Docker для Wazuh не использовались.

## Ресурсы и ограничения

| Ресурс | Значение из описания |
|---|---|
| CPU сервера | 4 vCPU |
| RAM сервера | Около 8 ГиБ |
| Диск сервера | Первоначально около 25 ГиБ; расширен примерно до 85 ГБ |
| RAM Astra Linux | Около 10 ГиБ на одном из этапов |
| Swap Astra Linux | 2 ГиБ |
| Корневой раздел Astra Linux | Около 23 ГиБ |

Значения даны в единицах исходного описания и относятся к разным этапам. Одновременное выделение 8 + 10 ГиБ двум ВМ при 16 ГБ физической RAM не является рабочей рекомендацией: нужны ресурсы хоста. Итоговое согласованное распределение не известно. Для повторения пересчитать ресурсы по выбранной версии Wazuh и доступной памяти; не выдавать эти цифры за минимальные требования продукта.

## Сеть

Итоговый режим — **сетевой мост (Bridged Adapter)**. Адреса могли меняться при выдаче в локальной сети. Используются заполнители `WAZUH_SERVER_IP`, `ASTRA_AGENT_IP`, `ADMIN_CLIENT`.

| Направление | Порт | Назначение | Достоверность |
|---|---|---|---|
| Agent → Manager | TCP 1514 | Передача событий | Указано в описании использования |
| Agent → Manager | TCP 1515 | Регистрация | Указано в описании использования |
| Браузер → Dashboard | TCP 443 | HTTPS-интерфейс | Доступ к интерфейсу описан |
| Административный клиент → сервер | TCP 22 обычно | SSH | SSH использовался; фактический порт не экспортирован |
| Filebeat → Indexer, внутри серверной ВМ | TCP 9200 обычно | TLS-индексация | Стандартный порт, точный listener не подтверждён |

Это описание потоков, а не готовый firewall-конфиг. Indexer не требуется открывать всей локальной сети; проверить фактический bind и необходимость каждого доступа. Полный перечень listeners и правил firewall не предоставлен. В All-in-One компоненты находятся на одной ВМ; граф в README описывает обработку событий, а не четыре отдельные машины.

## Поток данных

1. Агент читает настроенные журналы и отслеживает изменения файлов.
2. Manager принимает события, декодирует и анализирует их штатными механизмами Wazuh.
3. Filebeat передаёт обработанные данные в Indexer.
4. Dashboard запрашивает данные у Indexer и отображает их аналитику.

Регистрация агента и передача событий — разные соединения. Наличие агента в списке само по себе не доказывает успешную доставку каждого источника: это проверяется тестовыми событиями.
